# Описание проекта
## Исходная ситуация
Компания использует переговорные комнаты для проведения встреч. Бронирование комнат происходит через корпоративный чат: сотрудники договариваются между собой о времени использования переговорных.
Такой способ не позволяет централизованно отслеживать занятость переговорных комнат и может приводить к пересечениям в расписании, когда несколько сотрудников планируют использовать одну комнату в одно время.
## Цель проекта
Спроектировать единую систему онлайн-бронирования переговорных комнат для сотрудников компании.
## Пользователи системы
Пользователями системы являются сотрудники компании, авторизованные в личном кабинете.
## Основная логика системы
Сотрудник открывает сервис «Аренда комнат» и задаёт параметры поиска: дату, количество участников и необходимое оборудование.
Система подбирает переговорные комнаты, соответствующие указанным параметрам, и отображает доступные часовые интервалы в период с 10:00 до 18:00.
Сотрудник выбирает одну комнату и один или несколько последовательных часовых интервалов. Перед созданием бронирования система повторно проверяет доступность выбранного времени. Если комната свободна, создаётся бронирование.
Если на выбранную дату подходящих вариантов нет, сотрудник может выполнить поиск на ближайшие даты. Для будущей даты рассматриваются предыдущий и следующий календарные дни относительно выбранной даты. При поиске на текущую дату рассматривается только следующий день.
Сотрудник также может просматривать собственные бронирования, изменять их параметры или отменять их до момента начала встречи.
## Границы проекта
В рамках проекта рассматриваются:
- поиск переговорных комнат по дате, количеству участников и необходимому оборудованию;
- просмотр информации о переговорных комнатах;
- определение свободных часовых интервалов;
- создание и подтверждение бронирования;
- повторная проверка доступности комнаты перед созданием брони;
- поиск ближайших доступных вариантов;
- просмотр, изменение и отмена собственных бронирований;
- хранение данных о сотрудниках, комнатах и бронированиях.
В рамках проекта не рассматриваются внешние интеграции и проверка фактического состава участников встречи.
Основной сценарий, подробно рассмотренный в User Story, Use Case, BPMN и Sequence Diagram, — поиск и создание бронирования переговорной комнаты.

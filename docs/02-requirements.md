# Требования

Требования к системе бронирования переговорных комнат разделены на функциональные, нефункциональные требования и ограничения.

## Функциональные требования

### Поиск переговорной комнаты

- Система должна предоставлять авторизованному сотруднику доступ к сервису «Аренда комнат» из личного кабинета.
- Система должна отображать схему расположения переговорных комнат.
- При наведении или нажатии на переговорную комнату система должна отображать её название, максимальную вместимость, наличие флипчарта и проектора.
- Система должна предоставлять форму поиска переговорных комнат с параметрами: дата, количество участников, необходимость флипчарта и необходимость проектора.
- Система должна проверять корректность введённых пользователем параметров перед выполнением поиска.
- После нажатия кнопки «Поиск» система должна находить переговорные комнаты, соответствующие указанному количеству участников и требованиям к оборудованию.
- Для найденных комнат система должна получать информацию об активных бронированиях на выбранную дату и определять доступные свободные часовые интервалы.
- Система должна отображать для каждой подходящей комнаты её название, вместимость, оборудование и доступные временные интервалы.
- При поиске на текущую дату система не должна отображать для бронирования уже прошедшие временные интервалы.

### Создание бронирования

- Система должна позволять выбрать один или несколько последовательных свободных часовых интервалов одной переговорной комнаты.
- При выборе нескольких последовательных интервалов система должна объединять их в одно бронирование. Например, интервалы 10:00–11:00 и 11:00–12:00 образуют одно бронирование 10:00–12:00.
- После выбора комнаты и времени система должна предоставлять пользователю возможность перейти к бронированию, нажав кнопку «Забронировать».
- Перед созданием бронирования система должна отображать подтверждение с названием комнаты, датой, временем, количеством участников и оборудованием.
- Если пользователь отказывается от подтверждения, система не должна создавать бронирование.
- После подтверждения система должна повторно проверить доступность выбранной комнаты на указанный временной интервал.
- Если при повторной проверке выбранный интервал уже занят, система не должна создавать бронирование и должна уведомить пользователя о недоступности комнаты.
- Если выбранный интервал остаётся свободным, система должна создать бронирование.
- После успешного бронирования система должна отображать пользователю название комнаты, дату, время и количество участников.

### Поиск ближайших вариантов

- Если на выбранную дату отсутствуют подходящие свободные варианты, система должна сообщить об этом пользователю и предложить поиск ближайших вариантов.
- После согласия пользователя система должна выполнить поиск подходящих вариантов на предыдущую и следующую календарные даты относительно первоначально выбранной даты.
- Если первоначально выбрана текущая дата, система должна выполнять альтернативный поиск только на следующий календарный день.
- При альтернативном поиске система должна сохранять исходное количество участников и требования к оборудованию.
- Для найденных ближайших вариантов система должна отображать дату, комнату, вместимость, оборудование и доступные интервалы.
- Если ближайшие варианты не найдены, система должна предложить пользователю изменить параметры поиска.

### Просмотр бронирований

- Система должна отображать пользователю историю его собственных бронирований.
- Система должна позволять пользователю просматривать подробную информацию о собственном бронировании.
- Пользователь может иметь несколько активных бронирований.

### Изменение бронирования

- Система должна позволять пользователю редактировать собственные бронирования до момента его начала: изменять его дату, время, переговорную комнату, количество участников и требования к оборудованию.
- При изменении бронирования система должна повторно проверить соответствие выбранной комнаты вместимости, оборудованию и доступности нового временного интервала.
- Если новые параметры допустимы и выбранный интервал свободен, система должна обновить существующее бронирование.
- Если выбранный при изменении интервал занят или комната не соответствует новым параметрам, система не должна изменять бронирование и должна сообщить пользователю о невозможности изменения.

### Отмена бронирования

- Система должна позволять пользователю отменить собственное бронирование до момента его начала.
- При отмене система должна изменить статус бронирования на `CANCELLED`.
- Интервал отменённого бронирования должен становиться доступным для последующих бронирований.
- Система не должна позволять изменять или отменять уже начавшееся или завершённое бронирование.

## Нефункциональные требования

- Доступ к сервису должен предоставляться только авторизованным сотрудникам компании.
- Система должна позволять пользователю изменять и отменять только собственные бронирования.
- Система должна обеспечивать сохранение целостности данных при создании и изменении бронирований.
- При одновременных попытках пользователей забронировать одну комнату на один временной интервал система не должна подтверждать пользователю бронирование без повторной проверки его доступности.
- Система должна сохранять данные бронирования в соответствии с подтверждёнными пользователем параметрами.

## Ограничения

- Переговорные доступны для бронирования с 10:00 до 18:00.
- Система использует фиксированные часовые слоты: 10:00–11:00, 11:00–12:00, 12:00–13:00, 13:00–14:00, 14:00–15:00, 15:00–16:00, 16:00–17:00, 17:00–18:00.
- Минимальная продолжительность бронирования составляет 1 час.
- Можно выбрать только текущую или будущую дату.
- При выборе текущей даты прошедшие временные интервалы недоступны для бронирования.
- Количество участников должно быть положительным целым числом и не может превышать вместимость самой вместительной переговорной комнаты.
- В рамках одного бронирования можно выбрать только одну переговорную комнату.
- При выборе нескольких часовых слотов они должны быть последовательными.
- Поиск ближайших вариантов ограничен диапазоном ±1 календарного дня от выбранной даты. Прошедшие даты не могут отображаться.
- При поиске ближайших вариантов количество участников и требования к оборудованию остаются неизменными.
- Изменить или отменить бронирование можно только до момента его начала.
- Допустимые значения статуса бронирования `status`: `ACTIVE`, `CANCELLED`.
- Завершённым считается неотменённое бронирование, у которого `finish_datetime` меньше текущих даты и времени.
- Отменённые бронирования сохраняются в БД и физически не удаляются.
- Интеграции с внешними сервисами в рамках учебного проекта не рассматриваются.
